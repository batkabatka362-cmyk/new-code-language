## 1. Apple Silicon MLX Архитектур: Unified Memory ба VRAM Ханыг Нураасан нь

* **Хөгжүүлэгч:** Apple Machine Learning Research (Awni Hannun et al., 2024–2026).
* **Гол төсөл:** [`ml-explore/mlx`](https://github.com/ml-explore/mlx).

Хуучин NVIDIA GPU архитектурт CPU-ийн эх хавтангийн RAM болон GPU-ийн PCIe картын VRAM хоёр тусдаа байдаг тул загварын жин, идэвхжүүлэлтийг PCIe автобусаар нааш цааш зөөхөд асар их саатал гардаг байв.

```
Уламжлалт NVIDIA/PC Бүтэц:
  [ Системийн RAM (128GB) ] <==== PCIe Gen5 (64 GB/s Гацаа!) ====> [ GPU VRAM (Зөвхөн 24GB!) ]
                                                                       ^
                                                                       +-- 70B загвар багтахгүй!

Apple Silicon MLX (Unified Memory Architecture - UMA):
  +-----------------------------------------------------------------------------------------+
  |              НЭГДМЭЛ ФИЗИК САНАХ ОЙ (128GB / 192GB / 512GB LPDDR5X)                      |
  |                       Зурвасын Өргөн: 800+ GB/s (Хэт хурдан!)                           |
  +-----------------------------------------------------------------------------------------+
            ^                                  ^                                  ^
            | (0-Copy Шууд Хандалт)             | (0-Copy Шууд Хандалт)             |
            v                                  v                                  v
     [ Apple CPU Цөмүүд ]             [ Apple GPU Цөмүүд ]            [ Neural Engine (NPU) ]
```

### UMA-ийн Үндсэн Давуу Талууд:
1. **0-Copy Array Transfers:** CPU өгөгдөл бэлтгэж массив үүсгэхэд GPU тэр дороо санах ойн тухайн хаягаас ямар ч хуулах үйлдэлгүйгээр шууд уншиж тооцоолдог.
2. **VRAM-ийн Хана Үгүй Болсон нь:** Хэрэглэгчийн 128GB эсвэл 192GB санах ойтой Mac Studio дээр LLaMA-3.1 70B, Qwen 72B, бүр DeepSeek-ийн 236B загваруудыг хуваан таслахгүйгээр бүтнээр нь ачаалж инференс хийх боломж бүрдсэн.
3. **Wired Memory Optimization:** `iogpu.wired_limit_mb` тохиргоогоор үйлдлийн систем загварын санах ойг виртуал диск рүү (swap) шахахаас сэргийлж, санах ойд түгжин хамгийн дээд хурдаар ажиллуулдаг.

## 2. DeepSeek FP8 Mixed-Precision Сургалтын Математик Масштаб

* **Судалгаа:** *DeepSeek-V3 Technical Report* (arXiv:2412.19437, 2024).

8-битийн хөвөгч таслал (FP8 E4M3) нь сургалтыг 2 дахин хурдасгаж санах ойг 50% хэмнэдэг ч ердөө 8-битийн динамик хүрээтэй тул тоон сондгой үсрэлт (activation outliers)-ээс болж сургалт нуран унах өндөр эрсдэлтэй байдаг. DeepSeek нь үүнийг **Tile-Wise & Block-Wise** хоёр шатлалт микро-масштабаар шийдсэн.

```
                      [ Идэвхжүүлэлтийн Тензор X ]
                                   |
                                   v  (1 токен x 128 суваг бүхий жижиг хэсгүүдэд хуваана)
                      [ Tile-Wise Scaling: 1 x 128 ]
                                   |
                                   v  (Хэсэг бүр өөрийн s_x масштабыг динамикаар олно)
                      [ FP8 E4M3 Квантчлагдсан Tile ]
                                   |
                                   x  (Матриц Үржүүлэлт GEMM)
                                   |
                      [ Block-Wise Жин W: 128 x 128 ]
                                   |
                                   v
             [ FP32 Регистрт Хуримтлуулах (FP32 Accumulation) ]
```

#### Математик Томьёолол:
Идэвхжүүлэлтийн $1 \times 128$ хэмжээтэй плита (tile) бүрт масштабыг шууд бодит хугацаанд (Online Quantization) тооцно:

$$s_x = \frac{\max(|X_{\text{tile}}|)}{M_{\text{FP8}}}, \quad \widetilde{X}_{\text{tile}} = \text{Clip}\left( \left\lfloor \frac{X_{\text{tile}}}{s_x} \right\rceil, -M_{\text{FP8}}, M_{\text{FP8}} \right)$$

Жингийн матрицыг $128 \times 128$ блокоор масштаблана:

$$s_w = \frac{\max(|W_{\text{block}}|)}{M_{\text{FP8}}}, \quad \widetilde{W}_{\text{block}} = \text{Clip}\left( \left\lfloor \frac{W_{\text{block}}}{s_w} \right\rceil, -M_{\text{FP8}}, M_{\text{FP8}} \right)$$

Эцэст нь матриц үржүүлэлтийг хийхдээ алдаа хуримтлагдахаас сэргийлж GPU-ийн **FP32 регистрт нэмж нэгтгэдэг**:

$$Y_{\text{tile}} = s_x \cdot s_w \sum_{k} \widetilde{X}_{ik} \widetilde{W}_{kj} \quad (\text{FP32 Accumulation})$$

**Үр дүн:** 671 тэрбум параметртэй аварга загварыг 14.8 их наяд токен дээр BF16-тай яг адил төгс чанартайгаар, 2 дахин бага зардлаар сургаж дуусгасан дэлхийн цорын ганц бүтэц болсон.

## 3. EAGLE-2: Контекст Мэдрэмжтэй Динамик Ноорог Мод (Speculative Decoding)

* **Судалгаа:** *EAGLE-2: Faster Inference of Language Models with Dynamic Draft Trees* (Yuhui Li et al., arXiv:2406.16858, 2024).

Хуучин таамаглагч декодчилол (Speculative Decoding) нь тогтмол бүтэцтэй статик мод (Static Tree) ашигладаг байв. Гэтэл хялбар текстийн үед загвар 5-6 токеныг алдаагүй таадаг бол хүнд кодын үед 1-2 дахь токен дээрээ шууд татгалзагддаг.

```
EAGLE-1 (Статик Мод):
  Контекст ямар ч байсан байнга тогтмол 16 мөчиртэй мод үүсгэнэ (Тооцоолол хаягдана)

EAGLE-2 (Динамик Мод):
  [ Одоогийн Контекст ] ---> [ Draft Моделийн Найдвартай Байдлыг (Confidence) Хэмжих ]
                                  |
                                  +---> Хэрэв итгэл өндөр бол: Модыг урт, гүн ургуулна (Deep Tree)
                                  +---> Хэрэв итгэл бага бол:  Модыг өргөн, богино болгоно (Wide Tree)
```

- Загварын чанарт **0% өөрчлөлт орохгүй (Lossless)**.
- Токен үүсгэх хурд уламжлалт инференсээс **3-аас 5 дахин хурдасдаг**.
